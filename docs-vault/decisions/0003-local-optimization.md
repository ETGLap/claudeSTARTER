# 0003 — Local optimization helpers with explicit host boundaries

Date: 2026-09-15
Status: accepted
Related: [[0002-lean-defaults]], [[optimization-research]], [[specs/0002-optimization-layer]].

## Context

The user requested six unified optimization strategies active from task start, with our own
lightweight implementation informed by Caveman, RTK, code graphs and current model evidence.

## Decision

Put the default sequence in the imported core and detailed operating rules in an on-demand
policy. Add one Node CLI for lossless JSON formatting removal, bounded lexical code queries,
verified-catalog routing recommendations and recoverable log filtering. Preserve existing
hook wiring. Nested tool instructions document local contracts without duplicating the core.

## Consequences

No added runtime dependencies, paid calls or automatic indexing. Semantic prompt preservation,
simple-code judgment and concise generation are instructions rather than deterministic
checks. The graph is partial and must be confirmed against source. Catalog eligibility
requires current account/rate evidence and task validation; routing never dispatches calls.
Native prompt interception and active-model switching remain host responsibilities.
Character reductions are fixture evidence, not claimed end-to-end token savings.
